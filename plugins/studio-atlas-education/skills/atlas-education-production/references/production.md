# Protocollo operativo P0–P9
Riferimento canonico nel repository: docs/superpowers/specs/2026-11-12-atlas-education-production-publication-protocol.md, PR #307 in revisione. Questa copia è una guida operativa, non policy di pubblicazione.

| Fase | Consegna minima | Decisione |
|---|---|---|
| P0 | Brief e vincoli | Adeguatezza |
| P1 | Obiettivi, evidenze, riferimenti | Proposte vs Arena |
| P2 | Sequenza e attività | Coerenza pedagogica |
| P3 | File reali | Disponibilità e qualità |
| P4 | Consegna locale con hash e diritti | Integrità |
| P5 | Ricevuta autentica di acquisizione | Consenso esplicito |
| P6 | Rapporto di verifica | Prove reali e limiti |
| P7 | Revisione umana su versione esatta | PASS / REWORK / REJECT |
| P8 | Gate Atlas esistente | Conferma distinta, mai automatica |
| P9 | Fruizione autorizzata | Privacy, offline, accessibilità |

La scheda di consegna è un documento editoriale intermedio, non un nuovo ActivityPackage, non un manifesto intake e non una ricevuta. Il controllo locale non è un controllo di pubblicabilità. Lo schema canonico sperimentale richiede età 3–14, livello e riferimenti Arena autentici. Se manca binding, conservare come bozza editoriale; non produrre un falso pacchetto schema-valido. Anche per prodotti 14–18 serve un'estensione governata, non forzare la fascia. Diritti non chiariti, verifiche mancanti, audio non approvato o assenza di revisione impediscono il passaggio di stato. Non inserire dati alunni nei file, nella chat o nei report.
