# Atlas Percorsi — Compact Learning World Specification v1

**Status:** PROPOSED_PRODUCT_DIRECTION / HUMAN_REVIEW_REQUIRED  
**Runtime:** NOT_AUTHORIZED  
**Applies to:** first-cycle Atlas Percorsi where engagement depends on inquiry, decision, causality, construction, perspective or exploration  
**Evidence basis:** `research/common/game-world-learning-experience-benchmark-v1.md`

## 1. Product hypothesis

A strong Percorso should not feel like a digital lesson with game decoration.

It should feel like a **small world in which something matters and the learner can do something that changes understanding, state or outcome**.

Canonical world loop:

`ENTER → NOTICE SOMETHING → RECEIVE/ASSUME ROLE → EXPLORE → FIND/MAKE SOMETHING → ACT → WORLD RESPONDS → REINTERPRET → ACT AGAIN → RESOLVE OR OPEN NEXT QUESTION`

The world may be represented in 2-D. It does not require 3-D, avatars, multiplayer or persistent accounts.

## 2. World before interface

No learner-facing UI prototype should begin until a World Brief exists and passes Human Product Review.

The World Brief must answer:

1. **Where am I?**
2. **Who/what exists here?**
3. **What is happening before I arrive?**
4. **Why does my presence matter?**
5. **What can I inspect, move, change, build or decide?**
6. **Where is information hidden/distributed?**
7. **What changes when I act?**
8. **What remains unresolved and pulls me forward?**
9. **What meaningful artefact, decision or state will exist because I participated?**
10. **Would I still want to continue if badges, progress bars and scores disappeared?**

If these answers are weak, do not prototype the interface.

## 3. Learner role

The learner needs a **functional role**, not a decorative title.

Examples:
- investigator;
- planner;
- junior researcher;
- designer;
- field-team member;
- reporter;
- curator;
- technician;
- mediator;
- navigator.

A role is functional only if it changes:
- what the learner can inspect;
- what the learner can decide;
- what information becomes relevant;
- what product/action the learner is responsible for.

Avoid:
- “assistant” roles where the learner merely follows instructions;
- fake authority;
- identity/personality labels;
- emotional dependency on characters.

## 4. Productive agency

Agency means meaningful control over learning-relevant action.

Strong agency:
- choose where to investigate;
- decide which evidence to collect;
- build a representation;
- test a hypothesis;
- prioritise constraints;
- construct/design something;
- select a tool because the world demands it;
- revise after consequence;
- choose among defensible options.

Weak agency:
- choose which card to open;
- choose the correct option among obvious distractors;
- choose cosmetic dialogue;
- choose a route whose result is predetermined and pedagogically irrelevant.

## 5. Information architecture inside the world

Do not place all required information in instructional panels.

Information should be distributed across:
- places;
- objects;
- environmental state;
- visual traces;
- characters;
- dialogue;
- instruments;
- maps;
- logs/messages;
- sources/documents;
- data displays.

The learner should have opportunities to **discover, infer and connect**, not only consume.

## 6. The world must react

A learner action should produce a perceptible consequence.

Examples:
- a route opens/closes;
- a character changes plan;
- a model changes behaviour;
- a hypothesis gains/loses support;
- a design passes/fails a constraint;
- a source becomes more/less credible;
- a new location/data set becomes available;
- a previously hidden relation becomes visible.

Avoid:
- “Correct!” as the principal consequence;
- arbitrary reward animation;
- state changes unrelated to the learner's reasoning.

## 7. Productive output

Each Percorso should produce something meaningful inside the world.

Examples:
- reconstructed explanation;
- route/design;
- hypothesis;
- evidence set;
- recommendation;
- model;
- annotated map;
- report;
- comparison;
- decision with rationale.

The artefact should be a consequence of learning activity, not an extra worksheet after the experience.

## 8. Narrative distribution

Where narrative is used, it should be **distributed**, not front-loaded.

Prefer:
- events;
- environmental change;
- dialogue;
- character disagreement;
- objects;
- discovered messages;
- visual traces;
- response to learner action.

Avoid:
- long premise text;
- exposition that explains the whole problem;
- characters that repeat the instruction;
- final moral explaining the lesson.

The learner should understand more of the story because they explored and acted.

## 9. Curiosity engine

Every world needs at least one unresolved question that is **intrinsic to the world**.

Examples:
- What caused this?
- Which account can we trust?
- Why did the system fail?
- Which design will survive all constraints?
- Where is the missing information?
- What happens if this variable changes?
- Which recommendation should we make?

The question should not be:
> “Can you complete the learning objective?”

## 10. Rhythm

Recommended moment-to-moment rhythm:

`SEE → WONDER → TRY → NOTICE → CHOOSE → CONSEQUENCE → NEW QUESTION`

Avoid overly regular school-like rhythm:

`INSTRUCTION → TASK → CHECK → NEXT → INSTRUCTION → TASK → CHECK`

A Percorso may still contain validation, but validation should not dominate the experience.

## 11. Visual world quality

The visual layer should create **place, state and continuity**.

Required:
- stable spatial or conceptual anchors;
- a recognisable world identity;
- foreground/background hierarchy;
- environmental state visible without reading everything;
- age-appropriate craft and visual dignity;
- consistency of characters/objects/locations across states;
- minimal instructional chrome;
- mobile legibility.

Visual quality is not decoration. It helps the learner remember:
- where things are;
- what changed;
- what matters;
- what remains unresolved.

## 12. Interaction budget

Every interaction should justify itself.

A pathway should prefer a small number of **high-value mechanics** over many low-value gestures.

Example:
- inspect;
- collect;
- connect;
- build;
- test;
- revise.

Do not add:
- tapping;
- dragging;
- animation;
- inventory;
- avatar movement;

unless they carry learning-relevant meaning.

## 13. 2-D mobile world principle

Atlas may implement Compact Learning Worlds in lightweight 2-D/mobile form.

Possible forms:
- illustrated location with hotspots;
- map with stateful locations;
- workshop with objects/tools;
- lab bench;
- newsroom;
- museum;
- town/street;
- control room;
- field site;
- design studio;
- dossier/case room.

**World does not mean 3-D.**

The requirement is stateful environment + agency + consequence.

## 14. Social/perspective layer

Where the target involves perspective, evidence or decision, characters can carry:
- partial information;
- goals;
- disagreement;
- uncertainty;
- consequences.

Characters should not:
- exist only as mascots;
- praise the learner excessively;
- simulate intimacy;
- solicit private disclosures;
- act as pseudo-therapists.

## 15. Competence integration

The learning target must become useful because the world demands it.

Bad:
> “Use a causal map because this lesson is about causal maps.”

Good:
> The team needs to explain why the route failed. A timeline shows sequence but cannot answer the causal question; the learner chooses/builds a causal representation because it is useful.

This is the key distinction between **learning mechanic** and **school exercise mechanic**.

## 16. Transfer

Changed-context transfer should feel like a new problem in a new or evolved world, not a repeat quiz.

Transfer may:
- retain the learner role but change domain/context;
- retain characters but change problem;
- change world while preserving the cognitive tool.

Evidence must still require actual applied performance.

## 17. Desire-to-continue gate

Before implementation handoff, Human Review must answer:

> If this were not assigned by a teacher, is there a plausible reason an 11–14-year-old might want to continue for another few minutes?

This is not a popularity test.

Review:
- curiosity;
- agency;
- visual/world interest;
- consequence;
- meaningful challenge;
- social/narrative investment.

If the only reason to continue is “finish the exercise”, fail.

## 18. Anti-patterns

Reject:
- worksheet with avatars;
- story paragraph + generic cards;
- puzzle whose world is irrelevant;
- fake branching where every choice leads to the same state;
- gamified quiz loops;
- repeated sort/check/next;
- decorative 3-D;
- character dialogue that is actually teacher instruction;
- reward systems used to compensate for weak intrinsic activity.

## 19. Development workflow

Canonical sequence:

`COMPETENCE TARGET → WORLD BRIEF → ROLE/AGENCY MAP → INFORMATION DISTRIBUTION → CONSEQUENCE MODEL → EXPERIENCE CHOREOGRAPHY → VISUAL WORLD CONCEPT → LOW-FIDELITY PLAYABLE PROTOTYPE → HUMAN USE REVIEW → IMPLEMENTATION`

Not:

`COMPETENCE TARGET → UI MOCKUP → ADD STORY → ADD CHARACTERS → TEST`

## 20. Gate artefacts

Before learner-facing implementation, require:

1. World Brief;
2. Role/Agency Map;
3. Information Distribution Map;
4. Consequence Model;
5. Experience Choreography;
6. Visual World Concept;
7. Human Review note answering the desire-to-continue gate.

## 21. Authority boundary

This specification does not:
- require a specific game engine;
- require 3-D;
- require multiplayer;
- authorize student accounts;
- authorize analytics/tracking;
- authorize runtime/Q9;
- approve any current PW-STRATEGY-SELECTION prototype.

It is a proposed product-direction contract.
