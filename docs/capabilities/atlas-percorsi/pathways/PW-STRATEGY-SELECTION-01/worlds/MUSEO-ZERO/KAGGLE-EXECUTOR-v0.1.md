# MUSEO ZERO — Kaggle Executor v0.1

**Candidate:** MZ-VF-001  
**Factory:** TRAMA Visual Factory v0.1  
**State:** AUTOMATION_BRIDGE_PASS / GPU_PROVISIONING_NOT_QUALIFIED / NOT_RUNTIME_AUTHORIZED  
**Execution provider:** Kaggle Notebooks Free  
**Authority:** GitHub remains the governed source; Kaggle is compute-only

## 1. Purpose

Automate the operational bridge:

`TRAMA exact head -> Kaggle T4 -> notebook execution -> receipt/output -> GitHub evidence`

The operator should not need to:
- import notebooks manually;
- select files manually;
- download receipts manually;
- copy outputs back into GitHub manually;
- retry failed runs by hand.

The executor is one-shot and fail-closed.

## 2. Workflow

Canonical workflow:

`.github/workflows/visual-factory-kaggle-executor.yml`

Name:

**Visual Factory — Kaggle Executor v0.1**

## 3. Events

### Pull request

On PR changes to the executor/notebook contract:
- validate exact source revision;
- validate notebook JSON;
- validate fail-closed markers;
- confirm no credential material is embedded in the notebook;
- do **not** call Kaggle;
- do **not** consume GPU quota.

### workflow_dispatch

After the workflow exists on the default branch, a human may start one exact-head execution.

Required input:
- `exact_head` — exact 40-character TRAMA commit SHA.

No schedule and no automatic GPU run is configured.

## 4. One-time repository bootstrap

GitHub repository configuration requires:

### Secret

`KAGGLE_API_TOKEN`

Value:
a Kaggle API token intended for non-interactive CLI authentication.

The token:
- remains a GitHub Actions secret;
- must never be committed;
- is not passed into the Kaggle notebook;
- must not appear in artifacts or logs.

### Repository variable

`KAGGLE_USERNAME`

Value:
the Kaggle account username/slug that owns the private kernel.

This is not treated as a secret.

## 5. Kaggle kernel

Stable private kernel slug:

`<KAGGLE_USERNAME>/trama-visual-factory-q4-smoke`

Properties:
- private;
- Python notebook;
- Internet enabled for open model/tool downloads;
- GPU enabled;
- requested accelerator `NvidiaTeslaT4`;
- stable slug so each governed execution becomes a new Kaggle version;
- executions serialized by GitHub concurrency control.

The stable kernel is retained as provider-side execution history.

## 6. Source binding

The executor checks out exactly the requested `exact_head`.

It records:
- exact source SHA;
- SHA-256 of the governed notebook;
- generated Kaggle kernel metadata;
- raw Kaggle receipt;
- Kaggle logs;
- downloaded output;
- wrapper execution manifest generated by GitHub.

GitHub—not Kaggle—binds the raw execution result to the governed TRAMA exact head.

## 7. Evidence artifact

Every run attempts to upload:

`visual-factory-kaggle-<short_sha>`

Retention:
14 days for v0.1.

Evidence may contain:
- `EXACT_HEAD.txt`;
- `NOTEBOOK_SHA256.txt`;
- `kernel-metadata.json`;
- `push.log`;
- `status.log`;
- `kaggle.log`;
- raw notebook outputs;
- `raw-kaggle-receipt.json`;
- `execution-manifest.json`.

No credential file/token is included.

## 8. Pass/fail semantics

### PASS

Only:
`Q4_SMOKE_PASS`

This qualifies the bounded technical smoke test only.

It does not qualify:
- final visual quality;
- MUSEO ZERO Reference Lock;
- production publication;
- student runtime.

### Controlled non-pass

`Q4_OOM_FALLBACK_Q3_ALLOWED`

The executor stops red.

A Q3 fallback is a **separate run requiring a separate human decision**.
The executor does not automatically degrade quality.

### FAIL

Examples:
- missing Kaggle bootstrap;
- Kaggle quota/provider refusal;
- kernel execution error;
- timeout;
- missing receipt;
- receipt schema/decision mismatch;
- unexpected notebook failure.

No automatic retry.

## 9. Cost boundary

v0.1 authorizes:
- free Kaggle notebook execution only.

It does not authorize:
- paid Kaggle compute;
- paid Colab;
- paid Hugging Face Jobs;
- automatic provider failover to a paid service.

If free quota is unavailable:
**STOP / PROVIDER_UNAVAILABLE**

## 10. Security boundary

Kaggle receives:
- the selected notebook;
- public/open model download instructions;
- no student data;
- no TRAMA repository credentials;
- no GitHub token;
- no Kaggle API token inside notebook execution;
- no private curriculum/student records.

The GitHub Action receives the Kaggle API token only to operate the Kaggle CLI.

## 11. Authority boundary

The workflow may:
- submit a private kernel version;
- request a T4 accelerator;
- inspect status/logs;
- download provider outputs;
- create GitHub Actions evidence artifacts.

The workflow may not:
- merge PRs;
- publish Atlas;
- authorize runtime;
- promote Q3/Q4 visual quality;
- retry automatically;
- purchase compute;
- alter curriculum authority.

## 12. Human gates

Human authority remains required for:
1. configuring/rotating the Kaggle token;
2. triggering the exact-head GPU run;
3. authorizing any Q3 fallback after Q4 OOM;
4. Reference Lock;
5. PUBLISH_CANDIDATE;
6. runtime/public publication.

### Qualification decision

The GitHub <-> Kaggle automation bridge is technically proven.

No second GPU execution is authorised merely to repeat the same condition.

This finding is consistent with current Kaggle CLI reports documenting gaps between push-based accelerator requests and the environment actually provisioned.
